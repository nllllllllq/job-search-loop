# V1.4 紧凑公司列表、总览与设置折叠设计

## 背景与目标

本轮基于 V1.3 实际使用反馈，重点减少冗余交互和无效留白，提高岗位页、总览和设置页的信息密度。继续遵循“先完成核心功能，再根据试用决定是否补充极限与边界验证”。

## 1. 公司与岗位列表

- 移除公司别名确认、撤销和公司名称合并入口。
- 保留既有 `canonical_companies` 与 `company_aliases` 数据表，避免破坏旧数据库与备份；新界面和查询不再使用其中的数据。
- 岗位按原始 `company` 文本严格分组，不进行大小写、标点或空格模糊合并。
- 公司组默认折叠，只展示公司名、岗位数量、最近更新日期和组内最靠前的流程状态。
- 点击公司行展开或收起岗位列表。组按最近更新日期降序，组内岗位也按最近更新日期降序。
- 搜索与状态筛选继续作用于岗位；筛选后的结果再按公司分组。

## 2. 总览信息密度

- 总览统计新增“投递公司数”，按岗位原始公司名精确去重。
- 保留岗位总数、面试岗位数、完成复盘数、待确认建议等原有关键指标，并调整统计卡片布局以容纳新增指标。
- 流程日期线同时包含实际日期与预计日期，按日期从近到远排序，只展示最近十条。
- 流程日期线缩小行高、列宽、内边距和辅助文字字号。
- 总览各面板缩小标题区、卡片内边距和模块间距，提高一屏内可见信息量。

## 3. 岗位流程节点

- 移除右键删除菜单及对应交互。
- 节点编辑仍通过点击节点打开。
- 删除 × 仅在节点悬停或键盘聚焦时出现，尺寸缩小并移动到节点右上侧，避免遮挡节点名称和日期。
- 删除仍进入现有二次确认，不改变永久删除与阶段重排规则。

## 4. 设置页手风琴

- 每个设置模块保留清晰标题和简短摘要。
- 默认全部收起。
- 同时最多展开一个模块；点击新模块时自动收起旧模块，再显示该模块详情。
- 设置值、保存逻辑、错误提示和备份进度不因折叠而丢失。
- 恢复中断等必须立即处理的安全提示仍可显示在页面顶部，不藏入折叠区域。

## 5. 全局紧凑布局

- 统一减少各页面顶部标题区域的上下留白、标题与正文间距以及装饰区域高度。
- 保留现有纸张笔记式视觉语言，不重新设计颜色、字体或导航结构。
- 重点保证 1024×700 下标题、工具栏、首个核心模块无需过多滚动即可使用。

## 6. 数据与兼容

- 数据库不降级、不删除公司别名表，不需要新增迁移。
- 总览公司数由现有岗位数据实时计算，不新增持久化字段。
- 旧备份继续按现有迁移与校验逻辑恢复。

## 7. 安装包与日志

- 发布时升级应用版本，并在 `docs/CHANGELOG.md` 顶部新增本轮记录。
- Windows 安装包完成构建和 smoke 验证后复制到 `artifacts/<version>/`。
- 删除 `artifacts/` 中所有旧版本安装包和旧版本目录，只保留最新发布版本。

## 8. 核心验收

- 公司列表默认折叠，展开后显示正确岗位；不再出现别名合并入口。
- 总览公司数正确，流程日期线最多十条且日期降序。
- 岗位节点没有右键删除；小型 × 能触发确认删除。
- 设置页默认全部收起，且一次只展开一个模块。
- 主要页面顶部和总览模块明显变紧凑，在 1024×700 下无关键操作遮挡。
- 运行相关聚焦测试、全量测试、类型检查、生产构建、Windows 打包与 smoke。

## 9. 延后验证

- 大规模岗位数据下的展开性能。
- 超长公司名与极端窄屏排版。
- 广泛 Windows 环境与无障碍工具兼容矩阵。

这些项目在用户试用 V1.4 后，再决定是否进入单独加固阶段。
