# V1.5 岗位工作流与联网准备材料设计

## 背景与目标

本轮解决岗位录入、公司折叠列表、流程日期、总览信息密度和岗位准备生成五类核心使用问题。继续遵循“先完成功能再完美”的原则：优先跑通用户日常主路径，不扩大到极限性能、复杂网络异常矩阵或全部 AI Provider 兼容性测试。

本轮仍保持本地优先。岗位截图在用户确认前只形成临时预览，原图不保存；岗位准备由用户主动点击生成，并将公司、岗位、位置和完整 JD 发送至当前外部 AI 服务。岗位准备允许 Doubao 模型通过火山方舟 Responses API 调用内置 Web Search。

## 1. 公司折叠列表

### 分组与排序

- 继续按数据库中的原始公司名称精确分组，不恢复公司别名或自动合并。
- 公司组的排序由组内“进展最快”的岗位决定。
- 公司组内部的岗位使用同一阶段优先级：`offer > interview > assessment > applied > interested > other/closed`。
- `rejected`、`withdrawn` 和无法识别的其他状态归入最后一档。
- 同一优先级内按岗位最近更新时间倒序；公司组同级时按组内最近更新时间倒序，再使用公司名称形成稳定顺序。

### 展开内容

- 公司折叠行保留公司名称、岗位数量、最近更新和组内最快阶段。
- 展开后的岗位行不再重复公司名称。
- 岗位行主要显示岗位名称，并同时显示位置、兴趣度、阶段、更新时间和结果。
- 位置为空时显示“位置未记录”。

## 2. 岗位统一录入

### 默认入口与操作布局

- 打开“录入岗位”后默认进入“截图识别”。
- “手动录入”和“粘贴文本”保留为用户主动点击的次级入口。
- 截图尚未识别时，不显示“保存岗位”。
- “开始 AI 识别”固定在截图区域右下角。
- AI 返回预览后，右下角按钮变为“确认录入岗位”；只有该按钮会写入数据库。

### 识别结果与错误说明

- 必填字段仍为公司名称、岗位名称和完整 JD。
- 工作位置保持选填。
- AI 结果缺少必填字段时，保留已经识别出的内容，展开确认表单，并在顶部列出具体缺失项，例如“缺少：岗位名称、完整 JD”。
- 缺失字段在表单中同步标红；用户补齐后即可确认录入。
- 位置缺失只显示提示，不阻止保存。
- Provider、输入类型或结构校验失败时显示安全错误说明；不得只显示笼统的“识别失败”。

## 3. 岗位流程节点与日期语义

### 节点线

- 节点删除按钮缩小，固定在圆点的正上方，并且不遮挡名称或连线。
- 删除仍采用现有明确确认，且只影响当前岗位。
- 节点继续支持新增、编辑、排序和删除。

### 固定日期规则

用户不再选择日期记录模式，界面根据节点的 `canonicalStage` 自动决定：

- `interested`：单一日期“记录时间”，新增时自动填当天。
- `applied`：单一日期“投递时间”，默认流程创建时自动填岗位创建当天。
- `assessment`：两个日期，“收到通知时间”和“测评进行时间”。
- `interview`：两个日期，“收到通知时间”和“面试进行时间”。
- `offer`：单一日期“收到 Offer 时间”。
- `rejected`、`withdrawn`：单一日期“记录时间”。
- 自定义节点必须关联现有 canonical stage，并自动继承该阶段的固定日期规则。

为控制迁移范围，数据库继续复用 `expected_date` 与 `actual_date`：

- 对测评和面试，`expected_date` 保存通知时间，`actual_date` 保存进行时间；进行时间允许是未来日期。
- 对其他阶段，`actual_date` 保存其单一业务日期，`expected_date` 保持为空。
- 这些内部字段名不再直接出现在界面文案中。

## 4. 总览改版

### 顶部与数据摘要

- 删除总览顶部介绍区的英文标签、主标题和说明文案。
- 将“分析共性能力”移动到“能力主题”快捷入口附近。
- 数据摘要固定为同一行五项：公司数量、累计岗位、进入面试、完成复盘、待确认建议。
- 每项使用紧凑横向信息单元，降低高度、内边距和数字上下留白。
- 1024px 可用宽度下保持一行；仅在更窄的非目标窗口中允许自然换行。

### 待完成安排

- 删除“近期岗位”模块。
- 将“流程日期线”改为“待完成安排”。
- 只查询 `assessment` 和 `interview` 的进行时间，即对应节点的 `actual_date`。
- 只显示本地日期为今天或未来的记录，日期过去后直接消失。
- 按进行时间升序，最近的安排在前，最多显示 10 条。
- 不创建待办、通知或逾期状态。

## 5. Doubao 联网岗位准备

### 接口选择

- 只有岗位准备使用火山方舟 Responses API：`${baseUrl}/responses`。
- 使用当前已配置的 Doubao API Key 和模型；目标模型为 Doubao-Seed-2.0-mini 系列部署名称。
- 请求声明内置工具 `tools: [{ type: 'web_search' }]`，由模型完成联网搜索。
- 截图识别、项目导入、面试复盘和共性能力分析继续使用现有 `/chat/completions`，不在本轮整体迁移。
- 若当前 Provider 不是火山方舟或 Responses/Web Search 不可用，岗位准备必须明确失败并展示安全诊断，不静默退回模型旧知识。

### 外发范围

岗位准备只发送：

- 公司名称
- 岗位名称
- 工作位置（可为空）
- 完整原始 JD
- 当前“岗位准备”Prompt
- 固定 JSON 输出契约

不再读取、选择、预览或发送项目档案与问题库。历史材料中保存的旧资产快照继续可读，但新版本资产快照固定为空结构，保持数据库兼容。

### 固定输出结构

新版准备材料固定为五部分：

1. **公司与产品调研**
   - 公司业务与用户
   - 核心产品和商业模式
   - 近期公开方向
   - 该岗位可能负责的产品、用户和关键问题
   - 无法可靠确认的信息必须标注“待核实”
2. **Top 5 能力映射**
   - 严格五项，排名 1–5
   - 每项包含能力名称、JD 证据、岗位中的使用方式和面试证明建议
3. **STARS 公司阶段判断**
   - 仅允许 Startup、Turnaround、Realignment、Sustaining Success、Crisis
   - 包含阶段判断、依据、当前优先级和文化倾向
4. **理想候选人画像**
   - Typical Day 时间线
   - Superpower
   - Success Story 示例框架，不虚构用户真实经历
   - Quote
   - Pain Profile
5. **行动指南**
   - 自我介绍主线
   - 文化匹配表达
   - 三个岗位定制反问
   - 生成前的重点核实清单

界面不展示、不保存联网搜索来源链接。搜索得到的事实如不能稳定确认，必须在正文中标注“待核实”。

### 失败修复与诊断

当前失败风险来自两项结构性不匹配：岗位准备仍通过 Chat Completions 调用，且输出契约同时强制旧版六部分、项目要点与新版框架。V1.5 将：

- 新增仅供岗位准备使用的 Responses JSON 调用路径。
- 从 Responses `output` 中提取最后一条 `output_text`，清理可能的 Markdown JSON fence 后解析。
- 使用新版五部分 Zod schema 严格校验。
- 保留旧版和当前版本历史快照的读取兼容。
- 将 HTTP 状态、请求 ID 和已脱敏 Provider 信息写入现有安全任务错误，不保存 JD 或 Provider 原始响应。

## 6. 默认 Prompt 目标

默认“岗位准备”Prompt 将明确：角色、输入边界、联网研究任务、五部分结果、数量与字数范围、事实约束、待核实规则和严格 JSON 要求。Prompt 不得要求模型引用用户项目、问题库或编造个人经历。

Prompt 仓库对从未存在模板的数据库补入新默认值；如果现有内容与任一已发布的旧版默认模板完全一致，则自动升级为 V1.5 默认模板。用户已经修改过的 Prompt 不自动覆盖，避免丢失个人工作指令。

## 7. 核心验证范围

本轮验证主路径，不执行极限性能和复杂边界矩阵：

- 公司组与组内岗位均按阶段优先级排序，岗位行显示位置且不重复公司名。
- 录入弹窗默认截图；识别前无保存按钮，识别后可补齐缺失字段并确认。
- 流程编辑根据阶段显示正确日期名称；投递默认当天；删除按钮位于节点圆点上方。
- 总览五项同一行，介绍区和近期岗位消失；待完成安排只显示今天及未来十条测评/面试。
- Doubao Responses API 请求包含 Web Search，只发送岗位与 JD，不发送项目和问题。
- 成功返回五部分材料；无效 JSON、未开通 Web Search 和 Provider 请求失败时显示可操作的安全诊断。
- 运行聚焦测试、全量单元测试、类型检查和生产构建。

极端长 JD、大量公司/岗位、复杂时区边界、所有 OpenAI-compatible Provider 的 Responses 兼容性和大规模连续生成，留到用户试用后的单独验证阶段。

## 8. 不在本轮范围

- 不恢复公开岗位链接录入。
- 不保存或展示联网来源链接。
- 不增加提醒、系统通知或待办。
- 不修改项目文件导入的 AI 逻辑。
- 不迁移全部 AI 功能到 Responses API。
- 不恢复公司别名或公司名称合并。
