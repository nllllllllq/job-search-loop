# V1.6 首页、项目、岗位初始阶段与邮箱同步设计

## 目标

本轮优先把真实使用路径跑通，不做极限压力矩阵。改动覆盖四条主线：新岗位录入时直接确定当前阶段；项目以大块信息呈现并保留 AI 改写痕迹；首页把近期安排放到首屏并提供极简心得入口；邮箱在应用运行期间自动拉取招聘通知并更新匹配岗位。

## 1. 新岗位的初始阶段

- 岗位录入新增“当前阶段”，可选感兴趣、已投递、测评、面试、Offer，默认已投递。
- 日期规则固定，不让用户选择日期类型：感兴趣、已投递、Offer 使用“发生/收到日期”；测评、面试使用“通知日期”，实际进行日期后续在详情流程中记录。
- 初始日期默认当天，允许在保存前改动。
- 创建岗位时仍生成标准流程；选择感兴趣时在流程最前加入感兴趣，其他阶段沿用已投递、测评、面试、Offer。只有所选初始阶段写入日期，因此当前阶段立即正确显示。
- 新增或切换标准流程节点时，名称自动使用标准名称。自动名称第一次获得焦点时清空，方便直接输入自定义名称；用户已有的自定义名称不自动清空。

## 2. 项目档案与 AI 改写痕迹

- 数据库字段保持兼容，不迁移为新的复杂模型；界面将字段组织为项目概述、行动与决策、结果与证据、复盘与表达四块。
- 项目列表改为全宽横条，每条展示名称、简短概述、最近更新时间和查看入口；详情在列表下方展开。
- 文件仍先在本机提取文字，仅用户点击“AI 辅助解析”后发送提取文本。原始文件不保存。
- 项目 AI Prompt 明确：先判断哪些内容是真实项目，再按大块信息提取；允许在不改变事实的前提下补全表达，禁止虚构指标、职责和结果。
- 确认页保留原文证据。AI 重写时，原文以删除线展示，建议文本以高亮展示；用户确认后才写入项目。
- 支持直接粘贴补充材料走同一套 AI 解析与确认链路，避免再造一套项目优化 API。

## 3. 首页与极简心得

- 主导航和页标题“总览”改为“首页”。
- “待完成安排”紧跟统计数字，进入首页即可看见；其余分析模块继续向下排列。
- 全局右侧提供半隐藏的小圆形心得按钮，鼠标移入右侧区域或键盘聚焦时展开。
- 快速心得只输入正文；标题由正文第一行自动生成，不显示岗位、项目、问题或能力关联字段。保存仍复用现有心得接口。

## 4. 邮箱自动同步 MVP

- 首版采用通用 IMAP，而不是绑定单一邮箱厂商；适合 163、QQ、Gmail、Outlook 等开启 IMAP 的邮箱。
- 设置项包括邮箱地址、IMAP 主机、端口、TLS、用户名、授权码/应用密码、同步开关和轮询间隔。
- 授权码使用 Electron `safeStorage` 加密，保存在独立本机配置中，不进入 SQLite、备份或日志。
- 应用启动时同步一次，运行期间按间隔轮询；用户也可点击“立即同步”。应用退出后不常驻后台。
- 同步只读收件箱，不标记已读、不移动、不删除邮件、不下载附件。只读取新邮件的主题、发件人、时间和纯文本正文。
- 规则识别投递成功、测评通知、面试通知、Offer 和拒绝。只有当邮件内容能够唯一匹配现有岗位时才自动写入流程；无法唯一匹配的邮件保留为“待匹配”，不猜测岗位。
- 测评/面试邮件写入通知日期；投递/Offer/拒绝写入收到日期，并复用现有 currentStage 刷新逻辑。
- 邮件同步事件保存最小审计信息与处理状态，避免重复处理；不保存附件和完整原始邮件。

## 5. AI 可用性修复与验收

- Chat JSON 与 Responses JSON 使用同一套 Markdown fence 清理，避免模型返回 fenced JSON 时解析失败。
- “测试连接”同时验证普通 Chat JSON 与岗位准备所需的 Responses Web Search；页面分别报告失败环节。
- 准备材料继续只使用 JD、公司研究和岗位负责产品，不加入个人项目或问题库。
- 项目导入保留本地回退，但不再吞掉 AI 失败原因；确认页显示安全错误码、HTTP 状态和 request id，不显示密钥或响应原文。
- 更新失真的 E2E fake provider，使其覆盖当前 Responses API 和五部分准备材料格式。
- 使用提供的简历完成本地提取、分段、字段确认测试；向真实外部 AI 发送简历属于外发敏感信息，必须另有明确授权，不能由开发流程自动绕过。

## 非目标

- 本轮不做 Gmail/Outlook OAuth 审核、关闭应用后的系统常驻服务、附件 OCR、邮件发送、超长邮箱历史回溯。
- 不做复杂逐字 diff；以“原文删除线 + AI 建议高亮”提供清楚可确认的改写痕迹。
- 不做极限性能或复杂故障注入，先保证主路径可用。
