# 变更与设计日志

本文件记录面向用户的版本变更、设计决策和提交轨迹。每次发布前更新本文件；技术实施计划与验证待办位于 `docs/superpowers/`。

## 1.5.0 — 2026-08-08

### 岗位录入与列表

- 岗位录入默认打开“截图识别”，手动录入改为主动点击；识别前不再显示保存按钮，AI 识别操作移至右下角。
- AI 截图预览允许返回部分字段，并明确列出缺少的公司、岗位名称或完整 JD；工作位置保持可选。
- 公司与公司内部岗位均按 `Offer → 面试中 → 测评中 → 已投递 → 感兴趣` 排序，同阶段按最近更新时间排序。
- 公司折叠后的岗位行以岗位名称为主，不重复公司名，并补充显示工作位置。

### 岗位流程与日期

- 阶段日期改为固定语义：感兴趣/已投递自动记录当天；测评/面试记录通知时间和进行时间；Offer 只记录收到时间。
- 岗位详情的流程顺序保持普通流程顺序，不受岗位列表排序规则影响。
- 节点删除按钮缩小并对齐在圆点上方，保留确认删除。

### 总览与紧凑界面

- 总览只显示今天及未来待完成的测评、面试进行时间，按最近即将发生排序，最多十条；移除近期岗位模块。
- 公司数量、累计岗位、进入面试、完成复盘、待确认建议五项统计在支持宽度下保持单行紧凑排列。
- 移除总览介绍文案；所有页面的装饰性副标题与页码不再显示，公共页头压缩到 64px，内容更直接。

### 豆包联网岗位准备

- 岗位准备只使用公司、岗位、可选地点、完整 JD 与独立 Prompt，不再读取或发送项目档案和问题库。
- 新增豆包 Responses API 调用，使用模型原生 `web_search` 调研公司、产品、近期方向及岗位可能负责的产品。
- 默认 Prompt 细化为公司与产品调研、Map Competencies、Company Map、Dream Candidate Avatar、Action Guide 五部分；事实不足时明确标记“待核实”。
- 新格式结果按五部分展示；既有两代准备材料快照继续可读。确认生成后任务在后台运行，失败保留脱敏诊断。

### 验证与设计记录

- 全量 369 项测试、TypeScript 类型检查、生产构建与差异检查通过；极限性能和复杂边界矩阵继续留到试用后的独立阶段。

## 1.3.0 — 2026-08-01

### 录入、分组与弹窗体验

- 岗位截图录入改为 AI 图片结构化优先；模型不支持图片时，用户可明确选择“文字回退”或关闭，不会静默改用 OCR。
- 图片仅在本次请求中使用；PNG/JPG、数量、单图大小和总像素均在进入 AI 前校验。
- 相同公司可由用户明确确认别名后分组显示，支持撤销；绝不自动合并公司。
- 岗位、项目、问题和面试编辑窗口只允许通过右上角关闭；删除确认仍保留取消和确认操作。

### 项目文件 AI 辅助

- AI 根据本地提取并带行号的文本判断是否为有效项目，提供项目边界、缺失项、未使用内容和说明。
- 每个字段显示原文、AI 改写或 AI 建议及其依据；AI 建议必须逐项接受后才会写入项目档案。
- 无有效项目时显示原因且不提供保存路径。原始文件、文件名、路径和二进制不会外发或保存。

### AI 设置与安全

- 设置页可明确启用图片输入；不支持的文件输入保持关闭并在本地返回可识别的回退错误。
- AI 提供方错误和能力错误继续经过脱敏处理，避免 API Key、JD、图片或文件内容出现在界面或持久化数据中。

### 验证与兼容

- 旧备份可先恢复再迁移到当前数据库版本；新增提示词不会破坏历史备份。
- 常规回归通过：378 个测试、类型检查与生产构建输出检查。
- 极限性能、广泛模型兼容性和语义事实核验深度仍遵循试用后再决定的验证策略。

## 1.2.0 — 2026-08-01

### 设计原则

- 采用“先完成核心用户路径，再由试用反馈决定是否补充极限与边界验证”的交付方式。
- 核心路径、数据完整性、数据库迁移、凭据保护、外发确认和删除操作保护仍必须在交付前验证。
- 边界/极限文件、广泛模型兼容性、压力、重启竞态和别名模糊匹配被记录为试用后的验证待办，不阻塞本版发布。

### 准备材料：从同步等待改为后台任务

- 确认生成后不再停留在生成弹窗；任务在应用运行期间后台执行。
- 岗位详情与岗位列表显示“生成中、失败、上次已中断”状态。
- 同一岗位同时只允许一个准备材料任务，避免重复外发和重复生成版本。
- 应用退出后，未完成任务在下次启动显示为“已中断，可重新生成”。
- 失败不创建空准备材料版本；用户可重新打开选择界面再发起任务。

### AI 报错诊断与隐私保护

- 失败时可显示脱敏后的服务商诊断、HTTP 状态码和 Request ID。
- 保留普通的模型无效、额度不足等服务商说明。
- 自动屏蔽 API Key、Authorization/Bearer、`sk-...` 密钥、请求正文、Prompt、JD、项目内容、附件 data URI 和结构化回显。
- 任务数据库只保存任务状态、时间、岗位关联和经过二次脱敏的错误摘要，不保存 AI 请求、JD、项目或文件。

### 岗位流程操作

- 新岗位默认节点调整为：已投递、测评、面试、Offer。
- 已投递自动记录岗位创建当天为实际日期；不再默认加入“感兴趣”。
- 节点可右键打开删除菜单，也可悬停或键盘聚焦后直接点删除按钮。
- 删除确认与节点编辑分离；右键菜单支持点击外部或按 Esc 关闭。

## 从最初设计到首个可用版本 — 2026-07-27

### 产品定位与边界

产品最初被定义为本地优先的“整体求职规划管理助手”：形成从岗位录入、投递推进、面试准备、面试复盘到经验沉淀的闭环，而非以代写简历为核心。

- 岗位、项目、面试、题库和心得均由用户本地保存。
- 原始截图、录音和导入文件只用于处理，完成后不进入数据库或备份。
- AI 服务由用户自行配置；生成和复盘必须可回看、可确认。

### V1 设计与实现轨迹

1. 完成桌面端 V1 的产品设计与实施计划，确定总览、岗位、项目档案、问题库、心得和设置的信息架构。
2. 建立 Electron、SQLite、迁移、类型化 IPC 与导航基础设施。
3. 实现岗位闭环、项目/问题/能力/心得档案、可复用 AI 准备材料、面试复盘审核和本地备份恢复。
4. 完成首个 Windows 安装包与真实闭环验证。
