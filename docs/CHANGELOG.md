# 变更与设计日志

本文件记录面向用户的版本变更、设计决策和提交轨迹。每次发布前更新本文件；技术实施计划与验证待办位于 `docs/superpowers/`。

## 从最初设计到首个可用版本 — 2026-07-27

### 产品定位与边界

产品最初被定义为本地优先的“整体求职规划管理助手”，目标是形成从岗位录入、投递推进、面试准备、面试复盘到可复用经验沉淀的闭环；它不以代写简历为核心。

最早确认的原则包括：

- 岗位信息、项目档案、面试记录、题库与心得都归用户本地保存。
- 原始截图、录音和导入文件只用于处理，识别完成后不进入数据库或备份。
- AI 服务由用户自行配置；生成和复盘结果必须可回看、可确认。
- 岗位不只是单条记录，而是长期求职过程中的工具化台账。

### V1 设计与实现轨迹

1. **设计阶段**：形成桌面端 V1 的产品设计与实施计划，明确总览、岗位、项目档案、问题库、随想心得和设置等信息架构。
2. **本地基础设施**：搭建 Electron 桌面应用、SQLite 数据库、迁移机制、类型化 IPC 和基础导航。
3. **岗位闭环**：加入岗位记录、原始 JD、流程阶段、日期、反馈、位置和自定义节点。
4. **个人资产**：加入项目、问题、能力和心得档案，支持版本追溯与复用。
5. **AI 能力**：加入加密保存的用户自配 AI 服务、岗位准备材料、外发内容预览和不可变生成快照。
6. **面试学习闭环**：加入面试记录、复盘建议、用户审核后写入项目/题库/能力/心得的流程。
7. **数据安全**：加入本地备份恢复、迁移校验、审计快照保护和正式 Windows 打包验证。

### V1.1 体验与录入升级 — 2026-07-28

根据实际使用反馈，V1.1 将重点放在“录入更快、页面更紧凑、复盘入口更少但更集中”：

- 岗位详情改为直接显示 JD，并以紧凑流程线展示推进情况。

- 加入项目导入 AI 辅助与本地回退，并新增独立 Prompt。

## 1.2.0 — 2026-08-01

### 设计原则

- 采用“先完成核心用户路径，再由试用反馈决定是否补充极限与边界验证”的交付方式。
- 核心路径、数据完整性、数据库迁移、凭据保护、外发确认和删除操作保护仍必须在交付前验证。
- 边界/极限文件、广泛模型兼容性、压力、重启竞态和别名模糊匹配被记录为试用后的验证待办，不阻塞本版发布。

### 准备材料：从同步等待改为后台任务

- 确认生成后不再停留在生成弹窗；任务在应用运行期间后台执行。
- 岗位详情与岗位列表显示“生成中、失败、上次已中断”状态。
- 同一岗位同时只允许一个准备材料任务，避免重复外发和重复生成版本。
- 应用退出后，未完成任务在下次启动显示为“已中断，可重新生成”。
- 失败不创建空准备材料版本；用户可重新打开选择界面再发起任务。

### AI 报错诊断与隐私保护

- 失败时可显示脱敏后的服务商诊断、HTTP 状态码和 Request ID。
- 保留普通的模型无效、额度不足等服务商说明。
- 自动屏蔽 API Key、Authorization/Bearer、`sk-...` 密钥、请求正文、Prompt、JD、项目内容、附件 data URI 和结构化回显。
- 任务数据库只保存任务状态、时间、岗位关联和经过二次脱敏的错误摘要，不保存 AI 请求、JD、项目或文件。

### 岗位流程操作

- 新岗位默认节点调整为：已投递、测评、面试、Offer。
- 已投递自动记录岗位创建当天为实际日期；不再默认加入“感兴趣”。
- 节点可右键打开删除菜单，也可悬停或键盘聚焦后直接点删除按钮。
- 删除确认与节点编辑分离；右键菜单支持点击外部或按 Esc 关闭。
